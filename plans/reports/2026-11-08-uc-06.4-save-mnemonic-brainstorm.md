## 1. Problem-First Inversion (Phân tích Chiều sâu Vấn đề)

### 1.1. Nỗi đau thực tế: "Biến Dạng Đáp Án Gốc & Xung Đột Sở Hữu Bộ Thẻ Chung"
- **Thực trạng**: Khi học viên tìm được một mẹo nhớ hay (từ 3 phương án do Gemini sinh ra ở UC-06.3), họ muốn ghim mẹo nhớ này vào thẻ để trong các buổi ôn tập tiếp theo, ngay khi lật đáp án là nhìn thấy ngay.
- **Bẫy thiết kế nguy hiểm**: Nếu ghi đè mẹo nhớ trực tiếp vào trường `flashcards.back` (hoặc sửa đổi thực thể `Flashcard` dùng chung):
  - **Làm bẩn đáp án chuẩn học thuật**: Mặt sau thẻ cần ngắn gọn để đánh giá FSRS trong 3–5 giây. Nối thêm đoạn văn dài sẽ vi phạm *Nguyên tắc thông tin tối giản (Minimum Information Principle)*.
  - **Phá vỡ tính cá nhân hóa trên Bộ thẻ lớp học**: Một bộ bài giảng do Giảng viên tạo có thể có 60 sinh viên học chung. Sinh viên A thích thơ lục bát, sinh viên B thích câu chuyện ẩn dụ, sinh viên C không thích dùng mẹo. Nếu lưu vào thẻ gốc:
    - Sinh viên bị chặn vì không có quyền sửa (chỉ có quyền Read-only).
    - Hoặc sinh viên làm biến dạng đáp án của toàn bộ cả lớp.
- **Giải pháp**:
  - Tách bạch hoàn toàn giữa **Đáp án Chuẩn (Thực thể `Flashcard`)** và **Ghi chú Nhận thức Cá nhân (Thực thể `UserCardState`)**.
  - Mỗi học viên có trường `pinned_mnemonic` độc lập trong bảng `user_card_states`.

### 1.2. Thách thức Kỹ thuật Cốt lõi
1. **Khả năng Tinh chỉnh Lời văn (Inline Customization)**:
   - Dù AI sinh mẹo nhớ khá tốt, đôi khi học viên muốn thay đổi 1 vài từ ngữ địa phương, tên người bạn, hoặc thêm ký hiệu riêng để dễ thuộc hơn.
   - API phải chấp nhận chuỗi nội dung tùy chỉnh (`custom_content`), không ép buộc phải lấy y nguyên văn bản từ Gemini.
2. **Hiển thị Tinh tế trên Giao diện Lật thẻ (UC-05.2)**:
   - Khi học viên lật mặt sau thẻ trong phiên học Active Recall:
     - Khối trên: Hiển thị đáp án học thuật chuẩn (`flashcards.back`).
     - Khối dưới: Nếu `user_card_states.pinned_mnemonic != null`, hiển thị một khung ghi chú nổi bật (Callout Box màu vàng/hổ phách) kèm huy hiệu loại mẹo nhớ (`[THƠ VÈ]`, `[HÌNH ẢNH]`, `[ẨN DỤ]`) và icon cây bút cho phép sửa hoặc gỡ ghim.

## 3. Thiết Kế CSDL (PostgreSQL Schema)

Bổ sung 3 cột vào bảng `user_card_states` đã tạo từ UC-03.5:

```sql
-- Migration bổ sung trường Ghim Mẹo nhớ Cá nhân vào bảng user_card_states
ALTER TABLE user_card_states 
ADD COLUMN IF NOT EXISTS pinned_mnemonic TEXT DEFAULT NULL,
ADD COLUMN IF NOT EXISTS pinned_mnemonic_type VARCHAR(30) DEFAULT NULL, -- VISUAL, RHYME, ANALOGY, CUSTOM
ADD COLUMN IF NOT EXISTS pinned_at TIMESTAMPTZ DEFAULT NULL;

-- Chỉ mục hỗ trợ truy vấn nhanh các thẻ có mẹo nhớ của người dùng
CREATE INDEX IF NOT EXISTS idx_user_card_states_pinned 
ON user_card_states(user_id, card_id) 
WHERE pinned_mnemonic IS NOT NULL;
```

## 4. Đặc Tả API Contracts (C# ASP.NET Core)

### 4.1. Ghim Mẹo Nhớ Vào Thẻ Cá Nhân
* **Endpoint**: `PUT /api/v1/flashcards/{cardId}/mnemonic/pin`
* **Request Body**:
```json
{
  "mnemonic_type": "RHYME",
  "content": "Đang chạy (Running) bon bon trên đường,\nĐòi hỏi I/O phải nhường bước ngay.\nChuyển sang Chờ đợi (Waiting) ngủ say,\nKhi nào xong việc mới quay lại hàng!"
}
```
* **Quy trình Xử lý**:
  1. Xác thực `userId` từ JWT Token.
  2. Tìm bản ghi `user_card_states` tương ứng với `(userId, cardId)`. Nếu chưa có (ví dụ thẻ mới nạp nhưng chưa vào DB state), tự động khởi tạo bản ghi FSRS mặc định.
  3. Cập nhật `pinned_mnemonic = request.Content.Trim()`.
  4. Cập nhật `pinned_mnemonic_type = request.MnemonicType.ToUpper()`.
  5. Cập nhật `pinned_at = DateTimeOffset.UtcNow`.
  6. Lưu vào CSDL.
* **Response (HTTP 200 OK)**:
```json
{
  "success": true,
  "message": "Đã ghim mẹo nhớ thành công vào mặt sau thẻ.",
  "data": {
    "card_id": "f1a2b3c4-0001-4bad-9bdd-2b0d7b3dcb6d",
    "mnemonic_type": "RHYME",
    "pinned_mnemonic": "Đang chạy (Running) bon bon trên đường...",
    "pinned_at": "2026-11-08T09:30:00Z"
  }
}
```

### 4.2. Gỡ Ghim Mẹo Nhớ Khỏi Thẻ
* **Endpoint**: `DELETE /api/v1/flashcards/{cardId}/mnemonic/pin`
* **Quy trình Xử lý**:
  1. Tìm bản ghi `user_card_states`.
  2. Gán `pinned_mnemonic = NULL`, `pinned_mnemonic_type = NULL`, `pinned_at = NULL`.
  3. Lưu CSDL.
* **Response**: `HTTP 204 No Content`.

### 4.3. Lấy Thông Tin Mẹo Nhớ Đang Ghim
* **Endpoint**: `GET /api/v1/flashcards/{cardId}/mnemonic/pin`
* **Response (HTTP 200 OK)**:
```json
{
  "success": true,
  "data": {
    "is_pinned": true,
    "mnemonic_type": "RHYME",
    "pinned_mnemonic": "Đang chạy (Running) bon bon trên đường...",
    "pinned_at": "2026-11-08T09:30:00Z"
  }
}
```

## 5. Kịch Bản Kiểm Thử & Tiêu Chí Chấp Nhận (Acceptance Criteria)

1. **Personalization Isolation Test**:
   - Thẻ $X$ thuộc Bộ bài Công khai của Giảng viên.
   - Học viên A ghim mẹo nhớ dạng `RHYME`.
   - Học viên B ghim mẹo nhớ dạng `ANALOGY`.
   - Kiểm tra CSDL:
     - `flashcards.back` của thẻ $X$ không hề bị thay đổi.
     - `user_card_states` của Học viên A có `pinned_mnemonic_type = 'RHYME'`.
     - `user_card_states` của Học viên B có `pinned_mnemonic_type = 'ANALOGY'`.
2. **Custom Content Editing Test**:
   - Học viên chỉnh sửa 1 câu trong bài thơ trước khi ghim.
   - Kết quả: CSDL lưu chính xác đoạn văn đã sửa, không bị rollback về văn bản gốc của AI.
3. **Unpin Test**:
   - Gọi API `DELETE /pin`.
   - Kiểm tra: `pinned_mnemonic` trở về `NULL`, giao diện học tập không còn hiển thị khung mẹo nhớ nữa.
