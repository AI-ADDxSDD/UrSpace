## 1. Problem-First Inversion (Phân tích Chiều sâu Vấn đề)

### 1.1. Nỗi đau thực tế: "Hội chứng Khủng hoảng Nợ Thẻ (Study Debt Bankruptcy)"
- **Thực trạng**: Thuật toán lặp lại ngắt quãng FSRS v4.5 phụ thuộc sống còn vào việc học viên ôn tập đúng vào ngày thẻ đến hạn (`due_date <= Today`). Nếu học viên bận rộn hoặc quên mở ứng dụng trong 3–5 ngày:
  - Số lượng thẻ cần ôn tích lũy dồn dập từ 15 thẻ $\to$ 120 thẻ.
  - Khả năng nhớ lại (Retrievability $R$) rơi xuống mức nguy hiểm ($< 70\%$). Khi quay lại học, học viên phải bấm "Again" liên tục.
  - Tâm lý chán nản, cảm giác bị ngợp trước "núi thẻ nợ" dẫn đến việc từ bỏ học tập hoàn toàn.
- **Giải pháp**:
  - Dịch vụ nền Hangfire tự động nhắc nhở nhẹ nhàng vào đúng khung giờ người học đã chọn (mặc định 08:00 AM theo múi giờ địa phương).
  - Tích hợp thông điệp khích lệ: Nhắc nhở số lượng thẻ cần ôn kèm số ngày duy trì chuỗi học tập liên tục (**Streak**).

### 1.2. Thách thức Kỹ thuật Cốt lõi
1. **Tránh Spam phiền toái (Notification Fatigue)**:
   - Thẻ trong FSRS có thể đến hạn rải rác. Tuyệt đối **không** gửi thông báo lẻ tẻ.
   - Cơ chế giới hạn tần suất: Mỗi học viên chỉ nhận **tối đa 1 thông báo/ngày** (`last_reminder_sent_at` cách ít nhất 20 tiếng).
2. **Đa dạng Múi giờ (Timezone-Aware Scheduling)**:
   - Người dùng ở các khu vực khác nhau (Việt Nam UTC+7, Nhật Bản UTC+9, Mỹ UTC-5) có nhịp sinh hoạt khác nhau.
   - Hangfire chạy quét mỗi giờ một lần (`0 * * * *`), chuyển đổi giờ hiện tại sang múi giờ người dùng (`TimeZoneInfo`) để gửi đúng thời điểm họ mong muốn.
3. **Tiêu chuẩn Web Push hiện đại (VAPID Keys & Service Worker)**:
   - Gửi thông báo trực tiếp đến màn hình desktop hoặc điện thoại ngay cả khi trình duyệt đã đóng tab website.
   - Tuân thủ chuẩn IETF RFC 8292 (VAPID) thông qua thư viện `WebPush` C#.

## 3. Thiết Kế CSDL (PostgreSQL Schema)

```sql
-- 1. Bảng Cấu hình Thông báo Người dùng (User Notification Preferences)
CREATE TABLE IF NOT EXISTS user_notification_preferences (
    user_id UUID PRIMARY KEY REFERENCES users(id) ON DELETE CASCADE,
    email_enabled BOOLEAN NOT NULL DEFAULT TRUE,
    web_push_enabled BOOLEAN NOT NULL DEFAULT TRUE,
    reminder_hour INT NOT NULL DEFAULT 8, -- Giờ nhắc nhở trong ngày (0 - 23, mặc định 8h sáng)
    timezone VARCHAR(50) NOT NULL DEFAULT 'Asia/Ho_Chi_Minh',
    last_reminder_sent_at TIMESTAMPTZ,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- 2. Bảng Đăng ký Web Push của các Thiết bị (User Push Subscriptions)
CREATE TABLE IF NOT EXISTS user_push_subscriptions (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    endpoint TEXT NOT NULL,
    p256dh TEXT NOT NULL,
    auth TEXT NOT NULL,
    user_agent TEXT,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),

    CONSTRAINT uq_user_push_endpoint UNIQUE (user_id, endpoint)
);

-- Chỉ mục hỗ trợ quét nhanh học viên đến giờ nhận thông báo
CREATE INDEX IF NOT EXISTS idx_notification_pref_schedule 
ON user_notification_preferences(reminder_hour, timezone);
```

## 4. Kiến Trúc Luồng Xử Lý Nền (Background Processing Flow)

```
[Hangfire Scheduler (Cron: "0 * * * *")]
                   │
                   ▼
  1. StudyReminderSweepJob.ExecuteAsync()
     - Lấy UtcNow hiện tại.
     - Quét user có LocalHour == reminder_hour VÀ last_reminder_sent_at < UtcNow - 20h.
     - Kiểm tra có thẻ đến hạn: Count(user_card_states WHERE due_date <= UtcNow AND state != 'NEW') > 0.
                   │
                   ▼ (Đẩy từng User vào Hangfire Queue "notifications")
  2. SendStudyReminderWorker.ProcessAsync(userId, dueCount, streakDays)
       ┌───────────┴───────────┐
       ▼                       ▼
  [Web Push Service]     [Email Service]
  - Lấy push subscriptions. - Sinh HTML template FluentEmail.
  - Ký VAPID WebPushClient. - Gửi qua SMTP / SendGrid.
  - Gửi tới browser push service.
```

## 6. Kịch Bản Kiểm Thử & Tiêu Chí Chấp Nhận (Acceptance Criteria)

1. **Timezone Sweep Test**:
   - Học viên A đặt giờ nhắc lúc 8h sáng múi giờ `Asia/Ho_Chi_Minh` (UTC+7).
   - Khi server chạy lúc 01:00 UTC (tương đương 08:00 UTC+7) $\to$ Học viên A được quét vào danh sách gửi.
   - Khi server chạy lúc 02:00 UTC $\to$ Học viên A không bị quét lại.
2. **Spam Cooldown Test**:
   - Nếu `last_reminder_sent_at` là 4 tiếng trước (ví dụ vừa nhận thông báo thủ công) $\to$ Job quét tự động bỏ qua, không gửi trùng.
3. **Zero Due Cards Suppression Test**:
   - Học viên B đã hoàn thành hết bài học (`due_date > UtcNow` hoặc `due_count == 0`) $\to$ Hệ thống không gửi thông báo làm phiền.
4. **Invalid Subscription Pruning Test**:
   - Giả lập Google FCM trả về mã lỗi `HTTP 410 Gone` hoặc `404 Not Found` (người dùng đã reset browser) $\to$ Hệ thống tự động xóa bản ghi `user_push_subscriptions` tương ứng để giữ sạch database.
