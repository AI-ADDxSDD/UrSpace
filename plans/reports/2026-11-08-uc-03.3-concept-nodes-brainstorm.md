## 1. Problem-First Inversion (Phân tích Chiều sâu Vấn đề)

### 1.1. Nỗi đau thực tế: "Rác Đầu Vào = Rác Đầu Ra" (Garbage In, Garbage Out)
- **Vấn đề của AI**: Dù dùng mô hình Gemini hiện đại, AI vẫn có xác suất trích xuất nhầm các khái niệm không mang tính học thuật (lời cảm ơn, mục lục, tác giả, tiêu đề chương), hoặc chia nhỏ một định nghĩa nguyên khối thành nhiều khái niệm vụn vặt gây rối mắt.
- **Rủi ro nếu không có khâu Kiểm duyệt (Human-in-the-loop)**:
  - Cây kỹ năng 2D (UC-04.1) sẽ bị méo mó, chứa đầy các node rác.
  - Thuật toán FSRS và Dò lỗ hổng tri thức ($A(u)$ của TV3) sẽ tính toán sai lệch vì các khái niệm nền tảng bị phân mảnh.
- **Nỗi đau về Cấp độ Nhận thức**: Chuẩn 6 cấp độ Bloom học thuật (`Remember, Understand, Apply, Analyze, Evaluate, Create`) quá trừu tượng đối với học viên thông thường và khiến AI phân loại thiếu nhất quán. Rút gọn về **3 cấp độ trực quan: Cơ bản (Basic) - Trung bình (Intermediate) - Nâng cao (Advanced)** giúp cả AI lẫn học viên hiểu và thao tác dễ dàng hơn 10 lần.

## 2. Các Quyết Định Thiết Kế Đã Thống Nhất

| Hạng mục | Quyết định Kỹ thuật | Lý do & Giá trị mang lại |
| :--- | :--- | :--- |
| **Quản lý Vòng đời** | **Staging / Draft State (`status = 'DRAFT'`)** | Toàn bộ khái niệm do AI sinh ra nằm ở trạng thái `DRAFT`. Người dùng được tự do thêm/sửa/xóa an toàn. | **Phân loại Độ khó** | **3 Cấp độ: Basic / Intermediate / Advanced** | Tối giản, trực quan trên dropdown giao diện. Phục vụ đắc lực cho thuật toán $A(u)$ của TV3 (kiểm tra xem học viên có vững kiến thức Cơ bản trước khi học Nâng cao không). |

## 3. Thiết Kế CSDL Chi Tiết (PostgreSQL Schema)

```sql
-- Bảng quản lý Khái niệm tri thức (ConceptNodes)
CREATE TABLE IF NOT EXISTS concepts (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    deck_id UUID NOT NULL REFERENCES decks(id) ON DELETE CASCADE,
    document_id UUID REFERENCES documents(id) ON DELETE SET NULL,
    name VARCHAR(255) NOT NULL,
    summary TEXT NOT NULL,
    difficulty_level VARCHAR(20) NOT NULL DEFAULT 'BASIC', -- BASIC, INTERMEDIATE, ADVANCED
    source_page INT NOT NULL DEFAULT 1,
    source_excerpt TEXT, -- Đoạn trích dẫn gốc trong tài liệu PDF/Slide
    order_index INT NOT NULL DEFAULT 0,
    status VARCHAR(20) NOT NULL DEFAULT 'DRAFT', -- DRAFT (chờ duyệt), ACTIVE (đã nạp vào cây)
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- Chỉ mục tối ưu hóa truy vấn danh sách duyệt theo tài liệu và trạng thái
CREATE INDEX IF NOT EXISTS idx_concepts_document_status ON concepts(document_id, status);
CREATE INDEX IF NOT EXISTS idx_concepts_deck_status ON concepts(deck_id, status);
CREATE INDEX IF NOT EXISTS idx_concepts_order_index ON concepts(deck_id, order_index);
```

### 4.2. Chỉnh Sửa Khái Niệm (Tên, Tóm tắt, Độ khó, Trang nguồn)
* **Endpoint**: `PUT /api/v1/documents/{documentId}/concepts/{conceptId}`
* **Request Body**:
```json
{
  "name": "Tiến trình & Vùng nhớ (Process & Memory)",
  "summary": "Chương trình đang chạy có không gian địa chỉ riêng biệt...",
  "difficulty_level": "INTERMEDIATE",
  "source_page": 5
}
```
* **Response**: `HTTP 200 OK` kèm record đã cập nhật.

### 4.3. Thêm Mới Khái Niệm Thủ Công (Nếu AI bỏ sót)
* **Endpoint**: `POST /api/v1/documents/{documentId}/concepts`
* **Request Body**:
```json
{
  "name": "Khối điều khiển tiến trình (PCB)",
  "summary": "Cấu trúc dữ liệu của hệ điều hành chứa toàn bộ thông tin của một tiến trình.",
  "difficulty_level": "INTERMEDIATE",
  "source_page": 6,
  "source_excerpt": "Process Control Block contains information associated with a specific process."
}
```
* **Response**: `HTTP 201 Created`.

### 4.4. Xem Trước Tác Động Khi Xóa (Preview Impact)
* **Endpoint**: `GET /api/v1/documents/{documentId}/concepts/{conceptId}/delete-impact`
* **Response (HTTP 200 OK)**:
```json
{
  "concept_id": "c1a2b3c4-0001-4bad-9bdd-2b0d7b3dcb6d",
  "concept_name": "Tiến trình (Process)",
  "affected_flashcards_count": 4,
  "affected_prerequisite_edges_count": 2,
  "warning_message": "Xóa khái niệm này sẽ xóa kèm 4 flashcards và 2 liên kết tiên quyết trong đồ thị."
}
```

### 4.5. Xóa Khái Niệm (Cascade Delete)
* **Endpoint**: `DELETE /api/v1/documents/{documentId}/concepts/{conceptId}`
* **Response (HTTP 200 OK)**:
```json
{
  "success": true,
  "message": "Đã xóa khái niệm thành công cùng 4 flashcards và 2 liên kết phụ thuộc."
}
```

### 4.6. Xác Nhận Nạp Vào Bộ Thẻ (Commit) hoặc Hủy Bỏ (Discard)
* **Commit**: `POST /api/v1/documents/{documentId}/concepts/commit` $\to$ Cập nhật hàng loạt `status = 'ACTIVE'`.
* **Discard**: `DELETE /api/v1/documents/{documentId}/concepts/discard` $\to$ Xóa sạch các records `DRAFT` của document đó.

## 5. Kịch Bản Kiểm Thử & Chấp Nhận (Acceptance Criteria)

1. **Happy Path Query**: Gọi GET danh sách concepts trả về đầy đủ các trường, `status = DRAFT`, có kèm số lượng `flashcards_count`.
2. **Update Mutation**: Đổi `difficulty_level` từ `BASIC` sang `ADVANCED` $\to$ CSDL lưu chính xác, response trả về 200.
3. **Manual Insertion**: Thêm 1 concept thủ công $\to$ Gán đúng `document_id`, `deck_id` và `status = DRAFT`.
4. **Delete Cascade**: Xóa concept $\to$ Kiểm tra bảng `flashcards` không còn thẻ nào trỏ vào `concept_id` vừa xóa.
5. **Commit & Discard Integrity**:
   - Khi gọi Commit $\to$ Toàn bộ chuyển thành `ACTIVE`.
   - Khi gọi Discard $\to$ Toàn bộ bản ghi Draft bị xóa, CSDL sạch sẽ không để lại rác.
