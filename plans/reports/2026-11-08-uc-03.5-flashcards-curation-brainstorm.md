## 1. Problem-First Inversion (Phân tích Chiều sâu Vấn đề)

### 1.1. Nỗi đau thực tế: "Thẻ Quá Lan Man & Dư Thừa"
- **Nhược điểm của Flashcard do AI sinh**:
  - Gemini thường viết câu trả lời mặt sau (`back`) quá dài như một bài văn giải thích, vi phạm trực tiếp **Nguyên tắc Thông tin Tối giản (Minimum Information Principle)** của khoa học ghi nhớ. Flashcard hiệu quả phải ngắn gọn để học viên phản xạ và chấm điểm trong 3–5 giây.
  - Một số thẻ bị lặp lại ý hoặc hỏi những câu quá vụn vặt không trọng tâm.
- **Giải pháp**:
  - Giao diện gom nhóm thẻ theo từng `ConceptNode` giúp học viên nắm bắt ngữ cảnh bài học trước khi đọc câu hỏi.
  - Cho phép học viên **sửa nhanh trực tiếp (Inline Edit)** mặt trước và mặt sau trước khi lưu.
  - Hỗ trợ **Checkbox chọn lọc**: Học viên chỉ tick chọn những thẻ ưng ý nhất để nạp vào bộ học.

### 1.2. Quyết định Chiến lược: Lưu thẻ bị bỏ tick chọn làm Dataset Cải thiện AI
- Thay vì xóa vĩnh viễn (Hard Delete) các thẻ bị học viên bỏ chọn:
  - Hệ thống đánh dấu các thẻ này mang trạng thái **`status = 'DISCARDED'`**.
  - **Giá trị chiến lược**: Đây là tập dữ liệu phản hồi tiêu cực (Negative AI Feedback / DPO Dataset) vô giá để nhóm phân tích: *"Tại sao học viên từ chối thẻ này? Do quá dài, do sai kiến thức hay do câu hỏi tối nghĩa?"* từ đó tinh chỉnh system prompt của Gemini tốt hơn theo thời gian.

## 3. Thiết Kế CSDL (PostgreSQL Schema)

```sql
-- 1. Bảng quản lý Thẻ học (Flashcards)
CREATE TABLE IF NOT EXISTS flashcards (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    deck_id UUID NOT NULL REFERENCES decks(id) ON DELETE CASCADE,
    concept_id UUID NOT NULL REFERENCES concepts(id) ON DELETE CASCADE,
    front TEXT NOT NULL, -- Nội dung câu hỏi (hỗ trợ Markdown & LaTeX)
    back TEXT NOT NULL, -- Nội dung đáp án (hỗ trợ Markdown & LaTeX)
    card_type VARCHAR(30) NOT NULL DEFAULT 'STANDARD', -- STANDARD, CLOZE, MULTIPLE_CHOICE
    source_page INT NOT NULL DEFAULT 1,
    source_excerpt TEXT, -- Đoạn trích dẫn gốc trong tài liệu PDF phục vụ UC-03.6
    status VARCHAR(20) NOT NULL DEFAULT 'DRAFT', -- DRAFT (chờ duyệt), ACTIVE (đã nạp), DISCARDED (bị loại)
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- 2. Bảng quản lý Trạng thái Thuật toán FSRS cho từng Thẻ (UserCardStates)
CREATE TABLE IF NOT EXISTS user_card_states (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    card_id UUID NOT NULL REFERENCES flashcards(id) ON DELETE CASCADE,
    state VARCHAR(20) NOT NULL DEFAULT 'NEW', -- NEW, LEARNING, REVIEW, RELEARNING
    stability DOUBLE PRECISION NOT NULL DEFAULT 0.0, -- Độ ổn định S trong FSRS
    difficulty DOUBLE PRECISION NOT NULL DEFAULT 0.0, -- Độ khó D trong FSRS (1.0 -> 10.0)
    reps INT NOT NULL DEFAULT 0, -- Số lần đã ôn tập
    lapses INT NOT NULL DEFAULT 0, -- Số lần quên (bấm Again)
    due_date TIMESTAMPTZ NOT NULL DEFAULT NOW(), -- Ngày đến hạn ôn tập kế tiếp
    last_review TIMESTAMPTZ, -- Lần cuối ôn tập
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    
    CONSTRAINT uq_user_card_state UNIQUE (user_id, card_id)
);

-- Chỉ mục tối ưu hóa truy vấn
CREATE INDEX IF NOT EXISTS idx_flashcards_concept_status ON flashcards(concept_id, status);
CREATE INDEX IF NOT EXISTS idx_flashcards_deck_status ON flashcards(deck_id, status);
CREATE INDEX IF NOT EXISTS idx_user_card_states_due ON user_card_states(user_id, due_date, state);
```

* **Response**: `HTTP 201 Created`.

### 4.4. Thao Tác Chốt Hạ: Xác Nhận Nạp Vào Bộ Thẻ (Atomic Bulk Commit)
* **Endpoint**: `POST /api/v1/documents/{documentId}/flashcards/commit`
* **Request Body**:
```json
{
  "selected_card_ids": [
    "f1a2b3c4-0001-4bad-9bdd-2b0d7b3dcb6d",
    "f1a2b3c4-0002-4bad-9bdd-2b0d7b3dcb6d"
  ]
}
```
* **Cơ chế Xử lý trong 1 Transaction duy nhất**:
  1. Update các thẻ có ID trong `selected_card_ids` $\to$ `status = 'ACTIVE'`.
  2. Update các thẻ Draft còn lại không nằm trong danh sách $\to$ `status = 'DISCARDED'`.
  3. Update toàn bộ `concepts` và `concept_relations` của document $\to$ `status = 'ACTIVE'`.
  4. Bulk insert vào `user_card_states` cho từng thẻ Active: `State = New`, `Due = UtcNow`.
  5. Update `Document.Status = 'COMPLETED'`.
* **Response (HTTP 200 OK)**:
```json
{
  "success": true,
  "message": "Đã nạp thành công 24 flashcards vào Bộ thẻ. Hệ thống đã sẵn sàng cho phiên học đầu tiên!",
  "data": {
    "deck_id": "8f3b2e1a-4c5d-6e7f-8a9b-0c1d2e3f4a5b",
    "active_cards_count": 24,
    "discarded_cards_count": 6,
    "concepts_count": 10,
    "fsrs_ready": true
  }
}
```

## 5. Kịch Bản Kiểm Thử & Chấp Nhận (Acceptance Criteria)

1. **Grouped Query Test**: Gọi API GET flashcards $\to$ Dữ liệu trả về tự động nhóm đúng theo `concept_id`, có đầy đủ tên concept và danh sách thẻ.
2. **Inline Edit Test**: Sửa nội dung câu hỏi/đáp án chứa công thức LaTeX `$E = mc^2$` $\to$ Lưu DB nguyên vẹn không bị hỏng ký tự.
3. **Selection & Discard Test**:
   - Tài liệu có 30 thẻ Draft.
   - Gửi commit chỉ chọn 24 thẻ.
   - Kiểm tra DB: Đúng 24 thẻ mang `status = ACTIVE`, đúng 6 thẻ mang `status = DISCARDED`.
4. **FSRS Initialization Test**:
   - Kiểm tra bảng `user_card_states`: Có đúng 24 bản ghi mới được sinh ra cho `UserId` hiện tại, tất cả đều mang `State = New` và `Due <= UtcNow`.
5. **Chain Completion Verification**:
   - Kiểm tra `concepts`: toàn bộ mang `status = ACTIVE`.
   - Kiểm tra `concept_relations`: toàn bộ mang `status = ACTIVE`.
   - Kiểm tra `documents`: mang `status = COMPLETED`.
